# Global Fusion Console

A public, read-only operational intelligence console by **midnghtsapphire**. One React UI supports a Node/Express live-source runtime and an honestly timestamped GitHub Pages snapshot. The intelligence engine is vendored from [global-fusion-digest](https://github.com/midnghtsapphire/global-fusion-digest); no second classifier or collector is implemented here.

## Local development

Requires Node.js 22+ and pnpm 10.4.1.

```bash
corepack enable
corepack prepare pnpm@10.4.1 --activate
pnpm install --frozen-lockfile
pnpm dev
```

The managed fullstack template provides its own runtime environment. The public intelligence features do not need a database, an authenticated user, a paid LLM, or social publishing tokens. The preserved template authentication infrastructure is not presented as a console account system.

```bash
pnpm check
pnpm test
pnpm build
pnpm start
```

`pnpm build` bundles the app server and copies the vendored engine and validation schemas into `dist`. Those schemas are immutable code assets, not writable archives. No persistent production filesystem is assumed.

## Read-only live-source API

The fullstack runtime registers these endpoints on its existing Express listener:

| Endpoint | Response |
| --- | --- |
| `GET /api/v1/intelligence` | `{analysis, collection_status, cache, warning?}` |
| `GET /api/v1/digest?turn=1` | Snapshot plus Markdown report, six social draft strings, `mode: local_preview`, and `archive_written: false` |
| `GET /api/v1/health` | Service liveness and cache metadata; does not collect sources |
| `GET /api/v1/openapi.json` | Generated OpenAPI 3.1 document for these actual routes |

REST requests allow public cross-origin reads. Non-read methods return JSON 405; invalid turns return JSON 400; unavailable sources return JSON 503; unknown versioned routes return JSON 404. The REST limiter permits 60 reads/minute per client address and server instance. Turn values must be integers from 1 to 999999 and default to 1.

The same in-memory service backs tRPC `intelligence.snapshot` and `intelligence.render`, which the UI consumes through typed hooks. Its collection TTL is **10 minutes per instance**, concurrent collection requests share one in-flight promise, and failures back off for 30 seconds. A refresh failure may return explicitly marked stale data up to one hour old; older data is refused. Optional-source failures remain visible. A first collection failure never falls back to invented data.

Collections happen on request. There is **no schedule**. Preview turns never write an archive or change Audrey’s historical TURN002. No console operation publishes social content.

## GitHub Pages: the same UI, a fixed snapshot

```bash
pnpm build:pages
```

This calls the vendored official-source collector and pure report/draft builders, generates authentic JSON assets, then builds with `VITE_STATIC_MODE=true` and base `/global-fusion-console/`. Set `PAGES_BASE` to change the base for another repository. Output is `dist/public`. A custom tRPC link serves the bundled collection to the same UI hooks. Hash routing supports all pages without a backend.

The UI prominently labels the snapshot timestamp and says to refresh via workflow/rebuild. It does not claim that GitHub Pages supplies a live collection, 10-minute cache, or realtime REST API. The static report is preview turn 1 only. The turn control and in-browser refresh are disabled in this mode.

Static endpoints beneath the Pages base:

- `snapshot/intelligence.json`
- `snapshot/digest.json`
- `snapshot/report.md`
- `snapshot/social-drafts.json`
- `snapshot/manifest.json` (timestamp, mode, freshness instructions)
- `snapshot/fullstack-openapi.json` (reference only; clearly not served API paths on Pages)

The checked-in workflow `.github/workflows/pages.yml` deploys on push to `main` or manual `workflow_dispatch`, with immutable action references. There is no scheduled refresh. Enable GitHub Pages with **GitHub Actions** as its source. Builds collect current sources; a required-source failure fails the build instead of publishing invented data. Generated snapshot assets are ignored in source control and regenerated by each build.

## Console capabilities

Search/filter recent KEV entries by CVE, vendor, product, and operational priority. Open a keyboard-accessible remediation drawer with source descriptions and official links. Inspect source status and triage rationale, read CISA ICS and FBI IC3 cards, download report Markdown or JSON, and copy/download six unpublished social drafts. Integrations and privacy/support pages describe the actual supported boundaries.

The ink-navy/teal theme uses original Lucide Shield/Radio branding, not agency logos. Operational priority bins are rule-based triage labels, not CVSS or official agency severity scores. Counts cover the recent KEV sample, not the entire catalog.

## Updating the vendored core

Only the necessary modules are copied under `server/fusion-core` (`index`, `collect`, `network`, `parsers`, `validation`, `render`, `storage`) with schemas under `server/schemas`. The app does not invoke `runDigest` or vendor the MCP SDK. Preserve upstream copyright and license, recopy matching source and schemas after a verified upstream change, then rerun the checks and both builds. The storage re-export remains part of the upstream contract but is never called by public console routes.
